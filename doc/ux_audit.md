# UX/UI аудит frame_forge (Material Design)

Дата: 2025. Объект: визуальный редактор (`lib/src` + `example`).
Метод: статический анализ кода UI-слоя — дерево элементов, панель свойств,
канва, контекстные меню, color picker, снекбары, клавиатурный обработчик,
пример-приложение.

## Сильные стороны

- `GlobalKeyboardHandler` работает на `physicalKey` (не ломается на русской
  раскладке) и корректно защищает текстовые поля от перехвата Delete/Backspace.
- Undo/Redo с моделями действий (`controller/undo.dart`), стрелки двигают
  элемент по сетке, Alt — точный шаг, Shift — x5.
- Контекстное меню поддерживает навигацию с клавиатуры, фокус, подменю и берёт
  цвета из `colorScheme`.
- Кастинг видимой области на канве (`viewport.inflate(200)`) — правильная
  оптимизация.
- `PropertyTextField` с select-all-on-focus и обработкой Tab — удобный паттерн
  для панели свойств.

## P0 — критичные проблемы

### 1. Тема игнорируется почти везде: ~60 захардкоженных `Colors.*` в `lib/`
Редактор сломается в тёмной теме (в примере `darkTheme` вообще не задан):

| Где | Что захардкожено |
|---|---|
| `items.dart:109-114` | выделение в дереве — `Colors.amber`, фон — `Colors.white`/`Colors.grey`, рамка — чёрная |
| `properties.dart:39` | разделители таблицы свойств — `Colors.black` (в тёмной теме невидимы) |
| `main_canvas.dart:124,191` | фон канвы `Colors.grey.shade50`, элементы `bgColor: Colors.white` |
| `resizable_draggable_widget.dart:146` | рамка выделения — `Colors.red` |
| `snackbar.dart:12-21` | `Colors.green/red/orange/blue` вместо ролей colorScheme |
| `expandble_style.dart:29` | иконка — `Colors.black` |
| `example/*_button.dart` | текст кнопок аппбара — `TextStyle(color: Colors.black)` |

Плюс **три разных цвета выделения**: amber в дереве, red на канве, blueAccent
в сетке — пользователь не считывает «выделено» единым образом.

**Рекомендация:** завести `FrameForgeColors` (ThemeExtension) с ролями
`selection`, `canvasBackground`, `gridDot`, `selectionBorder` и заменить все
`Colors.*` на `Theme.of(context).colorScheme.*` / extension. В примере добавить
`darkTheme` — это сразу проверит тему на прочность.

### 2. Удаление местами не отменяется (Ctrl+Z не восстановит)
- Кнопка удаления на канве (`resizable_draggable_widget.dart:167`) и пункты
  меню в `component_page_menu.dart:159`, `component_group_menu.dart:139`
  вызывают `layoutModel.deleteItem()` напрямую — **мимо undo-стека**.
- Базовое меню (`menu.dart:192-196`) и Delete с клавиатуры идут через
  `controller.deleteSelected()` — **отменяемы**.

Пользователь не может предсказать, восстановит ли Ctrl+Z удаление.
Плюс `onChanged!` (`menu.dart:198`) — принудительный анврап, упадёт при
null-колбэке.

**Рекомендация:** все пути удаления вести через контроллер (undoable) и
показывать SnackBar с действием «Отменить».

### 3. Потеря несохранённых данных
`isSaved` отслеживается (`controller/project.dart`), но нигде не используется
как guard: Import/Example/New молча затирают текущий макет, нет индикатора
«грязного» состояния (точка/звёздочка в заголовке), нет подтверждения при
выходе (`PopScope`).

### 4. Баги, влияющие на UX
- **Color picker:** `int.tryParse(text, radix: 16) ?? 0`
  (`color_picker.dart:135`) — 6-значный hex `RRGGBB` превращается в
  **полностью прозрачный** цвет (alpha=0), мусорный ввод молча становится
  чёрным. Нет `errorText`, нет валидации.
- **Копия/вставка с иконкой корзины:** `component_page_menu.dart:135,142` —
  `Copy` и `Paste` используют `Icons.delete`.
- **Дублирующий пункт меню:** в `component_page_menu.dart` одновременно есть
  `List` (стр. 41) и `Expandable List` (стр. 113), оба добавляют
  `FormExpandbleList` — одинаковое действие под двумя именами.
- **Мёртвая ветка:** `items.dart:122` — `curPageType is ComponentPage` всегда
  false (сравнивается `Type`, а не экземпляр), `curComponentItem` из дерева
  не выставляется.
- **Потенциальный крэш:** `position!` в `items.dart:182` и
  `process_items.dart:164` — если контекстное меню вызвано клавишей
  Menu/клавиатурой без предварительного `MouseRegion.onEnter`, будет null-crash.
- **Невидимый ripple:** в `items.dart:104` `InkWell` обёрнут поверх
  `DecoratedBox` с непрозрачным цветом — чернила рисуются под ним, отклик на
  тап не виден.

### 5. Смешение языков без системы локализации
В одном продукте: `'Copy'/'Editing'` (меню) + `'Цвет:'`, `'Выбрать'`
(color picker) + `'Макет успешно сохранен'` (snackbar) + в примере
`Import`/`Export` рядом с `'Пример json'`. Нужен централизованный словарь
строк или `FrameForgeLocalizations` с делегатом.

## P1 — соответствие Material 3

### Контекстное меню
- Высота пункта 32px (`menu_item.dart:73`) — ниже минимального touch-target
  48dp M3; иконки 16px против 24dp в спеке.
- Нет горячих клавиш в пунктах (`Ctrl+C`, `Ctrl+V`, `Del`) — меню умеет
  больше, чем показывает.
- Нет состояния disabled (`MenuItem` не имеет флага `enabled`) — Paste активен
  при пустом буфере.
- Хедер `'Editing'` малоинформативен — лучше имя элемента.
- Подсветка фокуса `focusColor.withAlpha(20)` почти незаметна.

### Панель свойств
- Boolean -> DropdownButton «Yes/No» (`property_bool_widget.dart`) — по M3 это
  `Switch`; при `null` молча показывается «No», теряя tri-state.
- `DropdownButton` (M2-стиль) везде — M3-аналог `DropdownMenu`, для
  bool/alignment лучше `SegmentedButton`.
- Alignment через выпадающий список текстом `'Up left'` (кривой английский,
  правильно `Top left`) — каноничный паттерн — интерактивная сетка 3x3.
- Кнопка `'Color Picker'` (`property_color_widget.dart:54`) не показывает
  текущее значение; текст на цветной кнопке нечитаемен на тёмных цветах
  (`useWhiteForeground` считается, но не используется).
- Заголовок диалога `'Choose a color!'` — восклицание, несерьёзный тон; нет
  кнопки Cancel.
- Числовые поля: `int.tryParse(v) ?? 0` молча превращает опечатку в 0; нет
  `inputFormatters` (буквы можно ввести), нет `errorText`.

### Прочее
- Табы в примере — самодельные «пилюли» с чёрной рамкой
  (`maket_page_components_column.dart:116`) вместо `TabBar`/`SegmentedButton`.
- В AppBar стоят `ElevatedButton` с чёрным текстом — по M3 это
  `IconButton`/`TextButton` в actions.
- SnackBar без иконок и без action-кнопки, фикс. 3 сек, сырые цвета.
- `ExpandableStyle.buttonTextStyle` объявлен, но к `title` не применяется
  (мёртвый параметр).

## P2 — UX самого редактора

### Канва
- Ресайз без ручек: меняется только курсор, визуальных хэндлов нет — параметр
  `squareColor` прокидывается, но нигде не рисуется.
- Нет живого размера/позиции при drag/resize (тултип `320x240`).
- Нет контролов зума (+/-, «вписать», индикатор %), `minScale: 1` не даёт
  отдалиться.
- Нет направляющих выравнивания (snap только по сетке), нет линеек.
- Кнопка удаления на канве — голый `IconButton` без тултипа, стиля и
  подтверждения; висит над элементом и может перекрывать соседей.

### Дерево элементов
- Нет сворачивания веток — на больших макетах дерево бесконечно длинное.
- Нет иконок типов элементов, нет подсветки hover, `TextOverflow.clip` обрезает
  имена без ellipsis.
- Мёртвый код drag (`dragging` никогда не true) — drag-to-reorder и
  перетаскивание из дерева на канву не реализованы.

### Пустые состояния
- `'No selection'` голым текстом и `Container()` для пустой страницы
  (`components_and_sources.dart:40`) — нет подсказки «Кликните правой кнопкой,
  чтобы добавить компонент».

### Доступность
- 0 `Tooltip` и 0 `Semantics` во всём `lib/` — скринридер не узнаёт о
  выделении, цветовых свотчах, кнопках.
- Фиксированные высоты (`height: 25`, `height: 60`) сломаются при системном
  масштабировании текста.

### Адаптивность
- Пример: три равные `Flexible(flex: 2)` колонки без брейкпоинтов — на
  планшете/телефоне редактор неюзабелен. Нужен `LayoutBuilder`: на средней
  ширине — `NavigationRail`, на узкой — табы внизу.
- Таблица свойств с `FixedColumnWidth(50/100)` переполняется на длинных
  лейблах — лучше вертикальная компоновка «лейбл сверху, поле снизу».

### Производительность восприятия
- Сетка точек строится как `ListView` из `Row` из `SizedBox`
  (`grid_background_widget.dart`) — тысячи виджетов вместо одного
  `CustomPainter`.
- В примере `setState(() {})` на каждое событие шины перерисовывает всё
  приложение целиком.

## Приоритетный план работ

1. **P0:** цветовые роли + `darkTheme` в примере; единый undoable-путь
   удаления + SnackBar «Отменить»; guard несохранённых изменений; баги (hex,
   иконки, дубль меню, `position!`, мёртвый `is ComponentPage`).
2. **P1:** Switch для bool, `DropdownMenu`, сетка 3x3 для alignment, хинты
   клавиш и disabled в меню, тултипы, валидация полей ввода.
3. **P2:** ручки ресайза + живые размеры, контролы зума, empty states,
   сворачивание дерева, drag&drop из дерева, локализация, адаптивность,
   `CustomPainter` для сетки.

# Предложение: работа со списком из 50+ ComponentPage

## Текущее состояние (проблемы)

1. Вкладка Pages рендерит **все страницы сразу со всеми вложенными
   компонентами** (`items.dart`: Root -> каждая ComponentPage -> полная
   рекурсия детей). 50 страниц x ~10 компонентов = 500+ строк, построенных
   вложенными `ListView(shrinkWrap: true)` — всё строится жадно, без
   виртуализации.
2. Нет списка «только страницы»: чтобы переключить страницу, нужно искать её
   среди полного дерева.
3. Нет поиска/фильтра.
4. Нет группировки по флоу/фиче (онбординг, каталог, чекаут...).
5. Все новые страницы называются `'page'` (`component_root_menu.dart:21`) —
   50 неотличимых строк «page».
6. Добавление страницы — только правый клик по скрытому корню; нет
   переименования/дублирования/сортировки.
7. `curPage` — одиночное поле, логика переключения размазана по виджетам.

## Концепции

### 1. Master-detail: отделить список страниц от дерева компонентов
- Уровень 1: компактный список **только страниц** (иконка + имя + бейдж
  размера экрана), виртуализированный `ListView.builder`.
- Уровень 2: дерево компонентов **только текущей страницы** (существующий
  `Items`, но кормить его текущей страницей, а не корнем).
- Текущая страница подсвечена; переключение в один тап; канва следует за
  `curPage`.
- Хлебная крошка над канвой: `Макет / [ИмяСтраницы v]` — chooser с поиском.

### 2. Поиск/фильтр (instant)
- TextField над списком; фильтр по имени (без учёта регистра, fuzzy опционально);
  подсветка совпадений.
- Ctrl+P / Ctrl+K — быстрый переключатель страниц (command palette): стрелки +
  Enter, последние открытые сверху.
- Поиск и по именам компонентов: нашли компонент -> открыть его страницу +
  выделить + проскроллить к нему.

### 3. Группировка
- Вариант A (дешевле): **теги** — свойство `tags` у ComponentPage + ряд
  filter chips над списком. Сериализация через существующие Property.
- Вариант B: папки/группы страниц (новый тип Item-контейнер).
- Автогруппировка по размеру экрана (mobile/desktop) через SegmentedButton.

### 4. Виртуализация и сворачивание дерева
- Дерево компонентов выровнять в плоский список дескрипторов строк
  (depth, item, expanded) и рендерить `ListView.builder`.
- Состояние свёрнутости хранить в `Map<String, bool>`, сохранять между
  rebuild-ами, кнопка «Свернуть всё», авто-раскрытие только текущей страницы.

### 5. Операции над страницами
- Инлайн-переименование (двойной клик / F2), дублирование страницы (глубокая
  копия + `ensureUniqueIds`), drag-to-reorder в списке, удаление с подтверждением
  и undo.
- Автоимена «page 2», «page 3»... вместо одинаковых `'page'`.
- Бейджи: текущая, число компонентов, изменённая.

### 6. Быстрое переключение (command palette, Ctrl+K)
- Диалог с fuzzy-поиском по страницам (позже — стили, источники, процессы).
- Самый быстрый паттерн для 50+ элементов, дёшево в реализации.

## Рекомендуемый MVP (порядок)

1. Разделить вкладку Pages на master (список страниц, виртуализированный,
   подсветка текущей) — detail (дерево текущей страницы). Максимальный выигрыш.
2. Поиск по списку + Ctrl+K быстрый переключатель.
3. Теги/папки + фильтр-чипы.
4. Переименование/дублирование/reorder, автоимена с нумерацией.
5. Хлебная крошка/chooser над канвой.

## Заметки по модели

- Добавить `List<ComponentPage> get componentPages =>`
  `root.items.whereType<ComponentPage>().toList();`
- Добавить в контроллер `void switchPage(ComponentPage page)`: выставляет
  `curPage`, `curItemOnPage`, выделение и эмитит событие (сейчас логика
  переключения размазана по виджетам).
- `ensureUniqueIds` уже есть — использовать для дублирования страниц.
- Теги сериализуются как обычное Property страницы (fromMap мержит новые
  свойства в дефолтные, обратная совместимость сохраняется).
